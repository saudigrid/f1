# Saudi F1 Grid

موقع أخبار عربي متخصص في **رياضة الفورمولا 1 عالمياً** — كل الفرق، كل السائقين، كل جولة.
قسم السعودية واحد من الأقسام، لا محور الموقع.

---

## التشغيل السريع

```bash
npm install
cp .env.example .env
npm run sync      # يسحب بيانات الموسم الحقيقية (بلا مفتاح)
npm run dev
```

يعمل الموقع فوراً على <http://localhost:3000>، **بدون أي مفاتيح**.
كل المفاتيح اختيارية — كل واحد منها يُفعّل قدرة إضافية فقط:

| المتغيّر | بدونه | معه |
|---|---|---|
| `GOOGLE_API_KEY` **أو** `ANTHROPIC_API_KEY` | لا يعمل خط الأتمتة | الوكيلان يعملان |
| `NEXT_PUBLIC_SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` | القراءة من `src/data/*.json` | القراءة والكتابة في Supabase |
| `ADMIN_PASSWORD` | `/admin` مغلقة | لوحة المراجعة تعمل |
| `CRON_SECRET` | مسار الأتمتة يرفض كل الطلبات | جدولة الكرون (Vercel أو خارجية) تشغّله — راجع [`CRON.md`](./CRON.md) |
| `NEXT_PUBLIC_ADSENSE_CLIENT_ID` | مواضع إعلانية فارغة | AdSense يعمل |

## خط الأتمتة

ثلاثة وكلاء متسلسلين، **مخفيون بالكامل عن الزائر** — لا اسم ولا شارة ولا أثر في HTML:

```
مصادر RSS ──▶ ingest.ts ──▶ translate.ts ──▶ factcheck.ts ──▶ pipeline.ts
              جمع وتعنيد      صياغة عربية       تدقيق وتحقق      قرار النشر
              (بلا ذكاء       (نموذج)          (نموذج + بحث     (قواعد مكتوبة
               اصطناعي)                         على الويب)        لا نموذج)
                                   └──────┬──────┘
                                   طبقة المزوّدين
                                  Gemini أو Claude
```

**١. `ingest.ts` — الجمع.** يسحب خلاصات RSS ويجمع الأخبار المتطابقة عبر المصادر في
«عناقيد» بتشابه جاكارد. عدد المصادر في العنقود هو ما يعطينا لاحقاً *عدد المصادر
المستقلة* — نصف قرار النشر. لا يستدعي أي نموذج.

**٢. `translate.ts` — الصياغة.** ليس مترجماً حرفياً: يعيد بناء الخبر بالعربية من
الوقائع بأسلوب صحفي أصلي. مقصود لسببين — الترجمة الحرفية لنص محمي مشكلة قانونية،
وهي أيضاً تنتج عربية ركيكة.

**٣. `factcheck.ts` — التدقيق.** يبحث على الويب ليقارن كل واقعة بمصادر مستقلة عن
مصادر المسوّدة، ثم يعيد تقريراً منظّماً بدرجة ثقة. كم نداءً يستغرق ذلك؟ يعتمد على
المزوّد، والوكيل لا يعرف ولا يهتم — انظر «طبقة المزوّدين» أدناه.

**٤. `pipeline.ts` — القرار.** القرار **ليس عند النموذج**. النموذج يعطي تقييماً،
والقرار يُتخذ بقواعد مكتوبة صراحة في `config/pipeline.ts`:

```
أخطاء صريحة              ──▶ مراجعة
تكهّنات أو إشاعة          ──▶ مراجعة
تصنيف انتقالات / لوائح    ──▶ مراجعة
مصادر مستقلة < 2         ──▶ مراجعة
ثقة < 82                 ──▶ مراجعة
غير ذلك                  ──▶ نشر تلقائي
```

### التشغيل

```bash
npm run check             # فحص المزوّد أولاً — ندءان صغيران فقط
npm run pipeline          # التشغيلة الكاملة
```

`npm run check` يكتشف مشكلة مفتاح أو نموذج في ثوانٍ، بدل أن تكتشفها بعد اثنتي
عشرة محاولة فاشلة داخل التشغيلة الكاملة.

يشتغل تلقائياً **مرتين يومياً** — على Vercel عبر `vercel.json` مباشرة، وعلى
أي منصّة أخرى عبر خدمة كرون خارجية تستدعي `/api/cron/ingest`. المسار محمي بـ
`CRON_SECRET` حتى لا يستطيع زائر إشعال فاتورة API. تفاصيل الجدولة والمنصّات
في [`CRON.md`](./CRON.md).

### التكلفة والحصة

`maxArticlesPerRun` هو أهم صمّام أمان — يحدّ عدد الأخبار في كل تشغيلة.
بعده `effort` في `config/pipeline.ts` يضبط عمق التفكير لكل وكيل.

الإعداد الحالي مضبوط على حصة **Gemini المجانية: 20 طلباً يومياً**:

```
4 أخبار/تشغيلة × 2 تشغيلة/يوم × 2 نداء/خبر = 16 طلباً يومياً  ✓
```

الجدولة في `vercel.json` مضبوطة على `0 6,18 * * *` لنفس السبب. **ارفع الاثنين
معاً بعد الترقية** — رفع أحدهما وحده يخرق الحصة أو يهدر السعة.

## الترقية إلى تحقق مستقل

الوضع الحالي: **لا نشر تلقائي إطلاقاً**. وكيل التدقيق يعمل بلا بحث خارجي،
فما يجريه فحص اتساق داخلي مقابل مصادر المسوّدة — لا تحقّق مستقل. البنية جاهزة
للترقية، وهذه خطواتها بالترتيب.

### الخطوة ١ — فعّل البحث (اختر مساراً)

**المسار أ: فوترة Google** — الأبسط، صفر تعديل كود.
فعّل الفوترة على مشروع Google Cloud المرتبط بالمفتاح. ربط بحث جوجل يعمل فوراً،
وترتفع حصة الطلبات معه.

**المسار ب: مفتاح Claude** — تحقّق مستقل عن جوجل.
أضف `ANTHROPIC_API_KEY` إلى `.env`، ثم في `src/lib/config/pipeline.ts`:

```ts
factCheck: { provider: 'anthropic', model: 'claude-opus-5' },
```

الصياغة تبقى على Gemini إن أردت — الخلط مدعوم.

### الخطوة ٢ — تأكّد أن البحث صار يعمل

```bash
npm run check
```

يقيس القدرة فعلياً بدل الاعتماد على الإعداد المكتوب. حين تقرأ:

```
البحث على الويب : متاح ✓
التدقيق          : تحقّق مستقل حقيقي
```

فالبنية جاهزة. وما دام يقول «غير متاح»، المزوّد يتراجع تلقائياً إلى العمل بلا
بحث ويسقّف الثقة — لا يُسقط الخبر.

### الخطوة ٣ — قرار النشر التلقائي (لك وحدك)

في `src/lib/config/pipeline.ts`:

```ts
requireHumanReview: false,
```

**سطر واحد، ولا شيء آخر.** تُطبَّق عندها السياسة الهجينة: ثقة ≥ 82 و‏2 مصادر
مستقلة → نشر تلقائي؛ وتبقى التكهّنات وتصنيفات الانتقالات واللوائح على المراجعة
دائماً.

عمداً لا يتبدّل هذا تلقائياً مع توفّر البحث: **النشر التلقائي قرار تحريري، لا
نتيجة جانبية لتغيّر في خطة الفوترة.** وصفحة السياسة التحريرية ولوحة المراجعة
تقرآن هذا المفتاح مباشرة، فيتغيّر ما يراه القارئ معه — لا وعود لا تطابق الواقع.

### الخطوة ٤ — ارفع السقوف

`maxArticlesPerRun` في الإعدادات، وجدولة `vercel.json`. راجع حساب الحصة أعلاه.

## طبقة المزوّدين

الوكلاء لا يعرفون أي نموذج يعمل تحتهم. بينهم وبين المزوّد واجهة واحدة في
`src/lib/agents/providers/types.ts`، ولها تنفيذان:

| | Gemini | Claude |
|---|---|---|
| الحزمة | `@google/genai` | `@anthropic-ai/sdk` |
| المفتاح | `GOOGLE_API_KEY` | `ANTHROPIC_API_KEY` |
| البحث | ربط بحث جوجل | أداة بحث مستضافة |
| بحث + مخرجات مهيكلة | **نداء واحد** | ندائان (بحث ثم تنظيم) |

هذا الفرق الأخير هو سبب وجود الطبقة أصلاً: التنفيذان يخفيانه، فيبقى
`factcheck.ts` سطراً واحداً مهما تبدّل المزوّد.

### التبديل

في `src/lib/config/pipeline.ts` ← `agents`:

```ts
agents: {
  translate: { provider: 'gemini', model: 'gemini-3.8-flash' },
  factCheck: { provider: 'anthropic', model: 'claude-opus-5' },  // مثال: خلط
},
```

لا شيء آخر يحتاج تعديلاً. وإن ضبطت مزوّداً بلا مفتاح، يتحوّل النظام للمزوّد
الآخر مع **تحذير صريح في السجلّ** — تحوّل ظاهر لا صامت.

## بيانات الموسم

السباقات والنتائج والترتيب والسائقون والفرق تأتي من **واجهة Jolpica المفتوحة**
(متوافقة مع Ergast، مجانية وبلا مفتاح):

```bash
npm run sync              # الموسم الحالي
npm run sync -- 2025      # موسم بعينه
```

شغّلها بعد كل سباق. الكتابة كاملة في كل مرة، ولا تُلمس الأخبار.

**التعريب** في `src/lib/data/arabic-names.ts` — خرائط للسائقين والفرق والحلبات
والدول وأسماء الجوائز. أي معرّف جديد يظهر بالإنجليزية **مع تحذير صريح في مخرجات
المزامنة**، فلا يختفي سائق جديد بصمت ولا يظهر معرّف خام أمام القارئ:

```
⚠ معرّفات بلا ترجمة عربية — أضفها في src/lib/data/arabic-names.ts:
  • سائق: some_new_driver (Some Driver)
```

**الأتمتة:** أضف مسار مزامنة إلى `vercel.json` إن أردت تحديثاً دورياً، أو شغّلها
يدوياً — بيانات الموسم تتغيّر مرتين أو ثلاثاً في الأسبوع لا كل نصف ساعة.

### الأرشيف — يُشغَّل مرة، لا بعد كل سباق

ثلاث مزامنات تبني ما **لا يتغيّر**، فتُقرأ بعدها من القرص بلا نداء شبكة:

```bash
npm run sync:teams     # 214 صانعاً: المدى الزمني، الانتصارات، الألقاب
npm run sync:history   # مواسم كل فريق وسائقوه — من نتائج 26 ألف سباق
npm run sync:races     # مقالة كل سباق من ويكيبيديا العربية (1148 من 1172)
npm run sync:logos     # شعارات الفرق من كومنز — تنقية ثم جلب
```

⚠️ **`sync:history` و`sync:races` متتابعان بالكامل عمداً.** Jolpica وكومنز
يحدّان **التزامن** لا العدد اليومي، فطلبان متوازيان أخطر من مئتين متتابعين.
هذا ما أسقط البناء ثلاث مرات قبل أن نفهمه.

**الفرق السابقة** (`/teams/former`) مبنية كلها من هذه الملفات: 165 صفحة ثابتة
تُولَّد وقت البناء بصفر طلبات.

**دمج مركّبات الهيكل والمحرّك** في `src/data/team-aliases.ts`: Ergast يسجّل
«لوتس-كلايمكس» و«لوتس-فورد» صانعين مستقلّين عن «فريق لوتس»، فيتشظّى تاريخه على
أربعة معرّفات. الدمج يعيد الرقم الصحيح — 79 انتصاراً وسبعة ألقاب لا 45 وأربعة.

## شعارات الفرق

63 فريقاً من 214 لهم شعار حرّ على كومنز. البقية إمّا بلا شعار أصلاً (صانعون
دخلوا سباقاً واحداً في الخمسينيات)، أو شعارها محميّ.

⚠️ **البحث بالكلمات في كومنز يجد الاسم لا الجهة.** أعاد لـ«هوندا» صورة سيارة
هوندا صفراء، ولـ«إيغل» شعار شركة حواسيب، ولـ«تيرنر» شعار تينا تيرنر. المرفوضات
موثّقة واحداً واحداً في `src/data/logo-blocklist.ts`، ولا تعود إن أعدت المزامنة.

من لا شعار له يأخذ **شارة حروف** مولَّدة (`TeamCrest`) بلونه التاريخي — موحّدة،
ولا تدّعي أنها شعار.

### إضافة شعار بيدك

```bash
npm run logos:sync
```

يقرأ `public/teams-custom/<المعرّف>.png` ويكتب الفهرس، ثم يولّد
`شعارات-الفرق-المطلوبة.csv` بالناقص مرتّباً بالأهمية. **الاسم هو المعرّف** —
`team_lotus.png` لا `Team Lotus.png` — والسكربت يصرخ على كل اسم لا يطابق فريقاً،
لأن ملفاً مسمّى خطأً لا يظهر ولا يشتكي أحد.

الشعار اليدوي يسبق كل ما تجده المزامنة، تماماً كصور السائقين.

## الصور

طبقة مزوّدين على نفس نمط طبقة النماذج — `src/lib/images`. المنسّق يطلب «صورة
لهذا الخبر» ولا يعرف من أين تأتي.

```bash
npm run check:images      # يفحص الطبقة بلا استهلاك أي حصة نماذج
```

| # | المزوّد | متى |
|---|---|---|
| ١ | `licensed-feed` | صورة جاءت مع الخبر من ناشر بيننا وبينه اتفاقية |
| ٢ | `wikimedia` | صورة أرشيفية مرخّصة للسائق أو الجولة |
| ٣ | — | لا شيء ← نمط الهوية في البطاقة |

### الصلاحية

⚖️ **`LICENSED_SOURCE_IDS` في `src/lib/images/licensed-feed.ts` هو حدّ الصلاحية
كله.** معرّف مصدر غير مذكور فيه لا تُلمس صوره مهما كانت متاحة في خلاصته —
وجود الرابط في RSS ليس ترخيصاً.

عند تغيّر اتفاقية: احذف المعرّف من تلك المصفوفة. لا يوجد مكان آخر يمنح هذه
الصلاحية. (النطاقات في `next.config.ts` سماح شبكي لـ`next/image` فقط، لا صلاحية.)

### الإسناد

كل صورة تحمل `heroImageCredit` إلزامياً: المصوّر والمصدر والترخيص ورابط الأصل.
يُعرض تحت الصورة في صفحة الخبر وكشارة على البطاقة. هذا شرط تراخيص المشاع
الإبداعي، وليس تزييناً يمكن إخفاؤه.

### حدود المزوّد الاحتياطي

ويكيميديا يغطي **بالكيان لا بالحدث**: صورة للسائق أو للجولة، لا لحظة الخبر
نفسه. استخدام أرشيفي مشروع، لكن لا تقدّمه للقارئ كتصوير للحدث.

ثلاثة فحوص تحمي من نتائج خاطئة، وكلها كُتبت بعد أخطاء حقيقية ظهرت في الاختبار:

| الفحص | الخطأ الذي منعه |
|---|---|
| بوابة الصلة | صورة فريق **إبحار** SailGP فوق خبر عن جائزة إيطاليا |
| نوع الملف الأصلي | صفحة من **الجريدة الرسمية الأوروبية** (مصغّر PDF ينتهي بـ`.jpg`) |
| حدّ السنة + ترجيح السباقات | فيراري **1952**، وسيارة McLaren 720S **للطرق** |
| كشف الأرشيفي + تشكيلة الموسم | **مينارذي M198** من 1998، صُوّرت في عرض تاريخي يوم سباق 2025 |

**لماذا لا تكفي السنة وحدها:** السنة في اسم الملف هي تاريخ *الالتقاط* لا عصر
*ما في الصورة*. ملف `Minardi_M198_2025-09-06_Italian_Grand_Prix.jpg` يجتاز فحص
الحداثة بينما السيارة من 1998. لذلك يمرّر المنسّق **تشكيلة الموسم الحقيقية**
(من قاعدة البيانات) إلى طبقة الصور: اسم فريق أو سائق حالي يرفع رتبة الصورة،
واسم فريق غادر الشبكة يرفضها. القائمة في `VINTAGE_MARKERS`.

### إضافة مصدر مدفوع

اكتب مزوّداً يحقّق `ImageProvider`، وضعه في مصفوفة `PROVIDERS` بالموضع الذي
تريده، وأضف نطاقه إلى `next.config.ts`. خطوتان لا واحدة — عمداً.

## الإعلانات

خمسة مواضع، كلها عبر مكوّن `AdSlot` واحد يقبل **AdSense أو إعلاناً مباشراً** بلا
تعديل كود:

| الموضع | أين | جوال | ديسكتوب |
|---|---|:--:|:--:|
| `header-leaderboard` | أسفل الهيدر (لا فوقه) | ✓ | ✓ |
| `in-feed` | كل ٦ بطاقات داخل الشبكة | ✓ | ✓ |
| `in-article` | بعد الفقرة الثالثة | ✓ | ✓ |
| `sidebar-sticky` | عمود جانبي لاصق | — | ✓ |
| `mobile-anchor` | شريط سفلي قابل للإغلاق | ✓ | — |

قواعد ثابتة في الكود: **لا منبثقات، لا تغطية للمحتوى، لا فيديو تلقائي**، وكل موضع
له ارتفاع محجوز مسبقاً فلا تقفز الصفحة تحت يد القارئ (CLS). وكل موضع مُعلَّم بكلمة
«إعلان».

## الأداء والـ 3D

مشهد الهيرو **شادر واحد على مربّع واحد** — لا نماذج ولا ملفات ولا أضواء. `three`
تُستورد داخل `useEffect` فقط، فلا تدخل الحزمة الأولى.

يتوقف المشهد تلقائياً عند: طلب تقليل الحركة، أو جهاز بنواتين أو أقل، أو ذاكرة ٢
جيجابايت أو أقل، أو خروجه من الشاشة، أو انتقال الزائر لتبويب آخر. كثافة البكسل
مقيّدة بـ 1.5. وتحته خلفية ثابتة تعمل فوراً وتبقى إن تعذّر WebGL.

## الانتقال إلى الإنتاج

1. **Supabase**: شغّل `supabase/schema.sql` في SQL Editor، ثم أضف المتغيّرات إلى
   `.env`. الموقع ينتقل للقراءة منها تلقائياً — لا تعديل كود.
   *(المخزن المحلي للتطوير فقط: نظام ملفات Vercel للقراءة فقط.)*
2. **Vercel**: اربط المستودع، أضف كل متغيّرات البيئة، وسيلتقط `vercel.json` جدول
   الأتمتة تلقائياً.
3. **الدومين**: اضبط `NEXT_PUBLIC_SITE_URL` — تعتمد عليه خريطة الموقع وبطاقات المشاركة.
4. **البريد**: بدّل العناوين في `src/app/contact/page.tsx`.
5. **الخصوصية**: `src/app/privacy/page.tsx` صيغة أولية تحتاج مراجعة قانونية.

## ملاحظات مهمة

**الأخبار التجريبية.** بيانات الموسم في `src/data/` حقيقية بعد `npm run sync`،
لكن `articles.json` أخبار توضيحية كتبناها لملء الواجهة — **ليست أخباراً حقيقية**،
وبعض وقائعها لا تطابق الترتيب الحقيقي. تُستبدل بأول تشغيل ناجح لخط الأتمتة.

**حقوق النشر.** الموقع مبني على قاعدة: إعادة صياغة أصلية + إسناد + رابط، لا ترجمة
مقالات المصادر. قيد في قاعدة البيانات يمنع نشر أي خبر بلا مصادر. لا تُفعّل مصدراً
تمنع شروطه ذلك.

**رفض النموذج.** إذا رفض النموذج معالجة خبر، لا يُنشر — يذهب لطابور المراجعة. هذا
السلوك الصحيح تحريرياً، لا عطل.
